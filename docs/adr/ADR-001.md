# ADR-001: Build once, deploy the artifact

## Status

Accepted — 2026-07-22

## Context

The pipeline builds the site and, separately, deploys it. A deploy job
could rebuild from source instead of consuming a build artifact. But the
value of a pipeline is the guarantee "what passed the gates is what
shipped": every rebuild is a _second_ build, and our reproducibility work
(npm ci + committed lockfile) pins only the dependency _tree_ — not the
toolchain, the runner image, or nondeterminism in the build itself. We are
also about to have two deploy targets (dev and prod); "prod runs what dev
tested" must be provable, not hoped.

## Decision

We will build the site exactly once and have every downstream job — verify,
dev deploy, prod deploy — consume the same run-scoped `site` artifact. Its
contract is a built-site file tree rooted at the artifact root, including
`index.html`.

## Consequences

- The bytes tested are provably the bytes shipped; dev and prod run one
  identical artifact.
- The artifact name, layout, and required contents become a contract between
  producer and consumers. Build internals can change while that contract stays
  stable.
- Cost accepted: artifact upload/download plumbing and storage/transfer on
  every run, and a named contract to maintain — small next to the guarantee.
- Forces a later decision: artifact retention and how prod selects _which_
  run's artifact to promote (revisit when environments arrive).
